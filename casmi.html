01 / THE TASK

「分子の破片」から、元のつながりを当てる。

入力はLC-MS/MSで得たスペクトルと測定条件。出力は2D化学構造を表すSMILESの順位付きリストです。植物・哺乳類・微生物などに関係する天然物や、その類縁体が対象です。[1] [2]

構造は「原子の数」より難しい

分子式が同じでも、結合のしかたが違う構造異性体があります。正確な質量で候補を狭めても、最後は断片パターンを使ってつながりを見分ける必要があります。

CH₃–CH₂–OHエタノール / CCO
≠
CH₃–O–CH₃ジメチルエーテル / COC

どちらもC₂H₆O。化学の説明用の例で、コンペの分子や予測例ではありません。

1行の入力 ≠ 1個の予測

同じ分子に複数の測定があります。低・高エネルギー、正・負イオン、異なる付加イオンから得た手掛かりをmolecule_id単位でまとめます。

低エネルギー高エネルギー正イオン負イオン

採点の1票は「1分子」。スペクトル数が多い分子が、その数だけ重く採点されるわけではありません。[1] [2]

低エネルギーでは、壊れず残った前駆体や大きな断片が手掛かりになる場合があります。

実測値ではありません。エネルギー依存性は分子・装置・adductにより異なり、この図は一般的な傾向を単純化しています。

02 / THREE NOVELTY CLASSES

未知には3段階ある。解き方も変わる。

主催者は評価対象を以下の3クラスに分けています。各クラスの割合と、各分子の所属は非公開です。クラス名を予測して提出する課題ではありません。[2]

01

スペクトルが既知

公開ライブラリに参照スペクトルがある。

  • 似たスペクトルを探す
  • 一致した分子を候補にする
  • 装置差・測定条件差を吸収する

まず確実に得点したい領域

02

構造だけが既知

PubChemやCOCONUTに構造があるが、公開スペクトルはない。

  • 質量・分子式から構造DBを検索
  • 指紋や予測スペクトルで評価
  • 同じ分子式の異性体を見分ける

候補の収集と順位付けが重要

03

構造そのものが新規

PubChem・COCONUTの両方にない構造。新しい構造候補を作る必要がある。[18]

  • 構造生成・類縁体編集
  • 分子式・部分構造で制約
  • 観測スペクトルとの整合を確認

03 / METRIC & SUBMISSION

「当たったか」だけでなく、「何位で当たったか」。

MRR@25は、各分子で最初に正解した順位の逆数を平均します。正解が25位以内になければ0点。分子ごとに正解は1構造です。[1]

MRR@25 = (1 / U) × Σ score(u)
score(u) = 1 / rank(u)　［正解が1〜25位］、それ以外は0
FIG. 04 — 正解の順位を動かしてみる 対話デモ
3位

左ほど高得点。右端は「25位以内に正解なし」。

0.502位
0.333位
0.205位
0.1010位
0.0425位
この1分子の得点0.3333仮に400分子を採点するなら、全体への寄与は0.000833

例：3分子の正解順位が「1位・2位・圏外」なら、MRR@25 = (1 + 0.5 + 0) / 3 = 0.5。400分子の表示は計算例で、Public LBの採点数を意味しません。

SMILESの文字列一致ではない

公式はRDKit 2026.03.3で互変異性体を正規化し、InChIKey14で原子の接続を比較します。立体中心や互変異性体の表現違いは、この評価では区別されません。主催者は解答側も正規化前に立体情報を除去すると補足しています。[1] [19]

SMILES構造を読む
→

→
Key14答えと比較

同じ評価キーの候補は提出前に除重複。未処理のSMILESや元のInChIKeyだけで重複判定しない。厳密な呼び出し・例外処理は公式採点Notebookを採用する。主催者は現行採点器が公開v13と同一と確認済み。本調査ではコード本体は未取得。[6] [20]

提出ファイルの形

submission.csvに、分子IDごとに1行。smiles列に候補をセミコロン区切りで並べます。[1]

molecule_id,smiles
demo_001,CCO;COC

形式説明専用の架空ID・簡単な分子。実際の予測値ではありません。

  • 実行時のtestから全IDを取得する
  • 欠損・ID重複・25候補超過を防ぐ
  • 不正SMILESを除き、有効な候補を並べる
上位を守る価値が大きい：2位→1位の改善は1分子あたり+0.5。圏外→25位は+0.04です。正解を先頭付近へ動かす工夫は効きやすい一方、候補に正解がない分子は順位付けだけでは救えません。末尾への新規候補追加と、既存上位への割り込みは別々に評価します。

05 / CHEMISTRY-AWARE PREPROCESSING

モデルを大きくする前に、質量を正しく扱う。

adductの取り違えで正解を候補から落とすと、後段では回復できません。前処理は「きれいにする」だけでなく、「必要な情報を残す」設計です。戦略提案

前駆体m/z → 中性分子の質量

今回の公式テストadductは一価の例です。質量計算では水素原子とプロトンなどを区別した、検証済みのadduct定義を使います。

M = |z| × (m/z) − Δm
z：電荷数、Δm：中性分子からの質量変化
1分子からなる付加イオンの式。多量体は別途係数を考慮

[M+H]⁺ → M ≈ m/z − 1.007276
[M−H]⁻ → M ≈ m/z ＋ 1.007276
[M+Na]⁺ → M ≈ m/z − 22.989218
[M−H₂O+H]⁺ → M ≈ m/z ＋ 17.003289

数値はDa単位の質量補正例。全adductへの実装と丸め精度は検証する。水脱離を無視すると約18 Daずれる。

10種類のadductを考慮

公式Dataは次の10種類を列挙しています。学習側にはさらに多くの種類があります。[2]

[M+H]+[M+NH4]+[M-H2O+H]+[M-2H2O+H]+[M+Na]+[M+K]+[M-H]-[M-H2O-H]-[M+CH2O2-H]-[M+Cl]-

データ更新あり。運営は水脱離adductの追加とtrain再ダウンロードを告知しています。古いキャッシュに依存しないこと。[5]

Dataの列説明には「seven」という古い表記も残るため、7種類に固定しない。

閾値、top-N、質量許容幅は提案する比較軸で、最適値が判明しているわけではありません。

論点試したい処理落とし穴
質量精度分子内の中性質量を中央値などで統合。装置に合うppm許容幅を検証。許容幅を最初から狭く固定すると、誤差・adduct例外で正解を失う。
弱いピーク相対強度閾値と平方根変換を比較。低質量域を残す区間別top-Nも試す。弱い診断的ピークまで削る。全分子に同じ強い除去をかけない。
エネルギーcollision_energy_evを主に使い、欠損・複数値も表現する。eVとNCEは同じ数値尺度ではない。eV換算自体にも近似誤差がある。[2]
複数スペクトル条件別に符号化し、候補スコアを後から統合。単純平均・最大・品質重みを比較。全ピークを無条件に混ぜると、由来や条件の違いを失う。
ラベル品質trainの構造・adductと測定質量の整合、外れ値、出典別欠損率を調べる。trainのprecursor_error_ppmは正解依存。testの観測特徴としては利用できない。

何を順位付けの特徴にするか

  • 参照スペクトルとの一致と、質量誤差
  • 予測した分子指紋と候補指紋の適合度
  • 候補構造で説明できる断片・neutral loss
  • 候補から予測したMS/MSとの一致
  • 別エネルギー・別adductの測定との合意
  • 生成モデルのスコアと、構造の事前確率

質量誤差は候補構造から計算可能。異なるモデルの生スコアを直接足すのではなく、OOFでスケールと寄与を調整する。統合器の学習・調整に使ったOOFだけで性能を確定せず、別holdoutまたは入れ子CVで評価する。

分子式を1個に決め打ちしない

正しい分子式を落とすと、その分子式に限定した生成も検索も失敗します。上位の分子式候補を残し、候補構造に対して分子式の支持もスコアに含める設計を比較します。

上限性能の実験：正解分子式を与えた場合と推定分子式を使った場合をCVで比較すれば、「分子式推定」と「構造同定」のどちらがボトルネックか分かります。

正解分子式を与える実験は診断用。本番で利用できる性能として報告しない。

08 / VALIDATION IS THE STRATEGY

同じ分子を見ていたら、「未知に強い」とは言えない。

ランダムにスペクトル行を分割すると、別の測定・別のライブラリに同じ分子が残ります。評価の目的ごとに、何を隠すかを変えて検証します。戦略提案

NP examplesを「小さな本番」にする

enveda-np-examplesの250構造・1,151スペクトルは、本番と装置・処理が近い参照群です。他ライブラリにも同じ構造がある点を踏まえ、上のA/B/Cを作ります。[2]

  • 分子の評価キーでグループ化する
  • 調整用と最終確認用を分け、固定する
  • 分子・化学骨格・分子量・極性別に見る
  • 同分子式異性体を多く含む難しい候補群でも評価する

「よく知られた250分子」の偏りは残る。広い構造／骨格holdoutも併設し、この1群だけに最適化しない。

事前学習モデルの重複も調べる

検証構造を自作trainから除いても、公開重みがその分子のスペクトルや構造を学習している可能性があります。

  • 重みの学習元、版、対象構造を記録
  • 調べられない重複は「不明」と明示
  • Cでは構造のみの生成事前学習への混入も区別
  • foldごとに再学習できるモデルを基準として併設

DBから正解を除くだけで、モデルの記憶まで消せるわけではありません。真のde novo性能と単なる再生成を混同しない。

候補の漏れと順位の悪さを分解

100分子評価対象
80分子正解が候補プールに存在
60分子正解が25位以内

数字は架空例。ここからMRRは一意には決まらず、正解した各順位が必要。

診断指標を分けて記録する

Candidate recall：正解が最終ランキング前の候補集合に入る割合。候補数の上限も合わせて記録。

Hit@1 / Hit@5 / Hit@25：各順位以内に正解がある分子の割合。

条件付きMRR@25：正解が候補内にある分子だけで測る順位付けの質。25位外はここでも0点。

全体MRR@25
= Candidate recall
× 候補内分子の条件付きMRR@25

全分子の候補集合を固定したときの厳密な分解。例：0.80 × 0.50 = 0.40。

小さなPublic LBを過信しない：仮に全体400分子、その33%を採点するなら約132分子。1分子が圏外→1位になるだけで約0.0076変わります（比率からの概算）。分子単位のpaired bootstrap、複数fold、層別評価で改善の安定性を確認し、提出ごとに変更点を1つに絞ります。[3]
09 / EXPERIMENT PLAN

実験を「点数の伸びる理由」で並べる。

最優先は正しい採点と検索の確立。その後は候補再現率と条件付きMRRのどちらが低いかで投資先を変えます。以下は着手順の提案で、効果を測定した結果ではありません。戦略提案

優先実験合否を決める観測
P0最新データ・公式採点を固定。正しいadduct、評価キー、オフラインの最小提出を作る。ID全件、構造が有効、25件以下、正規化が一致、再実行が完走。
P1質量フィルタ＋参照検索。cosine/entropy、測定の統合方法を比較。検証AのMRR、Bでの候補漏れ、分子ごとのエラー原因。
P1構造DB索引を追加し、分子式のtop-Kを変える。検証BのCandidate recallと候補数。正解分子式を使った上限との差。
P2指紋予測・学習表現を追加。同分子式の難しい誤答を学習に使う。候補集合固定でのMRR、Hit@1、異性体パネルでの改善。
P2上位候補の予測MS/MSを使い、OOFでスコアを統合。同じ候補で条件付きMRRが上がるか。候補数当たりの追加時間。
P3構造生成を追加。数・条件・多様性・順位混合を分離して比較。検証Cで正解候補が増えるか。A/Bの上位を崩していないか。
P3誤りが異なるモデルを統合し、不確実な分子に計算を配分。単体より安定した改善、最大実行時間、メモリ、失敗率。

候補を増やすべきサイン

正解が候補集合に入らない。分子式の取り落とし、DB未収録、構造生成不足が原因候補です。幅を増やしたときの再現率と計算量をセットで測ります。

順位付けを磨くべきサイン

正解は候補内にあるが、上位が同分子式の別構造。モデルを増やす前に、その誤答との違いを説明する断片、複数条件の合意、hard negativeを調べます。

12 / GLOSSARY & EVIDENCE

用語と、調査の根拠。

図の多くは理解のために独自に作成した概念図です。測定済みの精度・学習結果・コンペの勝ち筋を示す実験結果ではありません。

迷いやすい言葉

m/z
イオンの質量を電荷数で割った量。中性分子の分子量と常に同じではない。
adduct / 付加イオン
プロトン・ナトリウムの付加や脱離など、観測されたイオンの形。
前駆体 / precursor
MS/MSで断片化する前のイオン。断片の元になるもの。
neutral loss
前駆体と断片の質量差から得る手掛かり。電荷・イオン種が対応するかに注意する。
SMILES
原子と結合を文字列で表す形式。同じ構造にも複数の文字列表現がある。
分子フィンガープリント
部分構造などの特徴をビットや数値のベクトルにしたもの。分子比較に使う。
tautomer / 互変異性体
水素の位置と結合が入れ替わる構造の関係。今回の採点では正規化して比較する。
de novo / 新規生成
登録済み構造の選択に限定せず、新しい構造候補を組み立てること。
OOF
各検証foldを学習から除いて得た予測。順位付けの統合や校正に使う。
domain shift
学習時と本番で装置・化学領域などが違うこと。ランダム分割の性能が当てにならない一因。
